# Workarounds Implemented

Each change follows the change-management template.

### W1 — Migration runner (`control-plane/app/migrate.py`, commits `f9f9d44`, raw-cursor fix after the `c9934e2` merge)

- **Change type:** Fix + Compatibility Layer (feature flag)
- **Risk:** Low. Off by default (`RUN_MIGRATIONS=false`); enabled only in `render.yaml`, whose services do not exist yet.
- **Impact:** Business: lead capture survives schema changes. Security: ledger tamper-proofing becomes real. Operational: `python -m app.migrate --status|--check`.
- **Why safe:** Postgres-only (SQLite untouched). One transaction under an advisory lock: a failure leaves the DB unchanged (tested), and a concurrent boot waits. Seeds are excluded. Every file is proven idempotent against `create_all` databases.
- **Rollback:** Set `RUN_MIGRATIONS=false`. Applied files are additive; the runner only adds `schema_migrations`. To also remove the trigger (not recommended): `DROP TRIGGER trg_events_no_update ON events`.

### W2 — Audit-hash key (`render.yaml`, `app/security.py`, commit `074e1a5`)

- **Change type:** Security Patch
- **Risk:** Low. Warning only; no startup is refused that was allowed before.
- **Why safe:** Nothing reads the warning. `generateValue` is the pattern `ADMIN_API_KEY` already uses in the same file.
- **Rollback:** Revert the commit. Keep the key stable once set: rotating it breaks correlation with older ledger rows.

### W3 — Shallow-clone guard (`tools/generate_search_assets.py`, commit `2273282`)

- **Change type:** Fix
- **Risk:** Low. Both workflows that run the generator use `fetch-depth: 0` (VERIFIED).
- **Why safe:** It exits 2 before writing anything. In a full clone, the output is byte-identical (gate passes).
- **Rollback:** Revert the commit.

### W4 — TestClient guard (`control-plane/tests/test_web_stack_guard.py`, commit `7c628cf`)

- **Change type:** Test (regression gate)
- **Risk:** None to runtime. It fails only when FastAPI is installed but TestClient cannot load.
- **Rollback:** Delete the file.

# Sentinel Core Evidence Workspace

## Scope

The Sentinel Core graph is a deterministic, browser-side visualization of ClearGlass's generated public-site page and related-link index, data/site-index.json. It is not a system telemetry map, intrusion-detection console, classified system, government product, or source of real-world authority or risk determinations.

The source index is generated by tools/internal_links.py. The graph preserves directed related-page assertions while computing pair-level structural metrics on a simple undirected projection.

## Evidence and identifiers

- Page IDs are stable, path-based identifiers of the form PAGE:<path>.
- Relationship IDs are formed from the lexicographically sorted endpoint paths. Each relationship export preserves one or two directed assertions and the source record reference for each direction.
- Relationship assertions point to data/site-index.json#pages[path="<path>"].related. This reference identifies an index record/field, not an independent observation.
- The inspector exposes indexed title/summary/about text, declared cluster, related-page direction, source reference, and the fact that the current schema does not store source reliability, extraction confidence, analyst review, first-seen/last-seen time, or independent-source corroboration.
- The UI uses text nodes for imported values. CSV cells are quoted and string cells beginning with spreadsheet formula characters are prefixed before export.

## Metric definitions

| Metric | Computation and interpretation |
| --- | --- |
| Degree centralisation | Freeman degree centralisation over unique undirected neighbours: sum(maximum degree − node degree) divided by (n − 1)(n − 2); defined as zero when n ≤ 2. |
| Relationship density | m / (n × (n − 1) / 2), where m is the number of unique undirected pairs. Self-loops are excluded and multiple directed assertions for the same pair do not create extra undirected edges. |
| PageRank | Directed PageRank over source related-page assertions, damping 0.85, 60 power iterations, dangling rank distributed evenly. Displayed node values are relative to the graph maximum, scaled 0–100. |
| Betweenness | Brandes shortest-path betweenness over the unweighted undirected projection. Displayed node values are relative to the graph maximum, scaled 0–100. |
| Cluster modularity | Modularity measured against repository-declared clusters. It is not the result of an automatic community-detection run. |
| Link reciprocity | Numerator is the count of unique undirected pairs with both directions present; denominator is all unique undirected pairs. It is a property of one generated index, not independent evidence. |
| Inbound sparsity | A heuristic: zero for the home page; otherwise round(100 / (1 + inboundDegree² / 2)). It is not an exposure, threat or risk score. |
| Structural priority | round(0.45 × PageRankRelative + 0.35 × BetweennessRelative + 0.20 × InboundSparsity). It is only a sorting aid inside this graph. |
| Candidate links | Adamic–Adar heuristic over currently unlinked pairs sharing at least three neighbours. The list is not evaluated and must not be described as a validated forecast. |

Computation duration is measured in-browser for graph analysis plus layout; DOM rendering and index retrieval are excluded. The computation time is not a source-observation timestamp.

## Export formats

The Evidence JSON export follows the schema identifier clearglass.sentinel-evidence-export.v1. It includes export/computation metadata, input scope, graph semantics, metric definitions and parameters, entity and relationship identifiers, supporting index references, structural findings, and limitations. Evidence-quality fields absent from the source are marked unavailable rather than filled with guessed values.

The Evidence CSV export flattens entities, relationships, and findings into rows. It includes source references, direction assertions, and evidence-quality/temporal gaps. Both exports are generated as local browser downloads; they do not call an external export service.

## Explicit limitations

- The static index does not supply trusted update timestamps, per-edge observation times, historical snapshots, or first-seen/last-seen fields. The client records when it retrieved the index, but this is not proof of source freshness.
- The source data does not contain reliability assessments, extraction confidence, analyst review states, independent-source corroboration, or calibrated model-uncertainty estimates.
- Reciprocal paths can come from the same generated index and cannot be treated as independent corroboration.
- There is no live host/network/SIEM/IDS telemetry. Findings refer to graph structure or data quality only.
- The application does not have a contextual language model connected to this graph. Its current summaries and metrics are deterministic.
- A front-end interface alone does not provide server-side authorization, audit-log integrity, or tamper-evident evidence storage. Such controls require backend identity, authorization, logging and retention infrastructure.

## Validation

Run the existing site tests and JavaScript syntax validation in a repository checkout:

    python -m pytest -q tests/test_sentinel_core.py
    node --check station-chat.js

The cache version in sw.js is incremented when the console asset changes so an older cached script is less likely to mask the updated workspace.

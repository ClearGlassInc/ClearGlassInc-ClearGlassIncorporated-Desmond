# GitHub Actions remediation report

**Audit scope:** all workflow files in `.github/workflows/` at the reviewed commit.  
**Execution decision:** no hosted workflows were dispatched. Local inspection cannot prove repository secrets, protected-environment reviewers/branch rules, external action provenance review, or a production rollback owner. Deploying or mutating workflows remain blocked until a repository administrator records those controls.

## Outcome

The audit found no malformed YAML, missing local reusable workflow/action, mutable external action reference, missing executable-job timeout, direct secret interpolation in `run`, or `pull_request_target` trigger after remediation. Checkout credential persistence is now explicit: read-only jobs disable it, while the few audited jobs that execute `git push` opt in explicitly. The GitHub Pages workflow now grants `pages: write` and `id-token: write` only to the deployment job.

Statuses below mean:

- **valid and ready** — source-verifiable controls pass; hosted execution still requires the remote preflight below.
- **valid but needs improvement** — structurally valid, but a non-blocking or least-privilege issue remains.
- **broken and requiring immediate patching** — a deterministic source defect prevents safe execution.
- **unsafe and requiring governance changes before execution** — mutation/deployment lacks a source-visible protected approval boundary or rollback control.

## Ordered remediation and rollout

1. **Keep blocked:** do not dispatch rows classified unsafe. Add protected environments with required reviewers, branch restrictions, concurrency, a named rollback owner, and a tested last-known-good recovery procedure.
2. **Restore fail-closed checks:** enable the repository Dependency Graph, then remove `continue-on-error` from Dependency Review. Review the IP scan heuristic and make confirmed secret findings blocking without creating false-positive merge outages.
3. **Narrow the military pipeline:** move OIDC and other write scopes from workflow level to the sole consuming jobs; remove the scheduled path to release tagging or bind release mutation to a protected approval environment. Replace placeholder deployment logging with a real, separately reviewed deployment contract before claiming deployment.
4. **Approve mutation bots individually:** for ARTEMIS provenance, content, feed, dependency, orchestrator, and workflow-doctor writers, require PR-only output and prevent direct protected-branch updates. Record bot-loop prevention and rollback ownership.
5. **Remote preflight:** verify action SHAs against upstream release provenance, secret names/availability (never values), environment protection, branch rules, GitHub Pages source, and artifact retention. Record actor, ref, inputs, commit SHA, environment decision, and rollback owner.
6. **Canary:** run only a read-only `workflow_dispatch` workflow first. Capture the run URL, job results, relevant log excerpts, artifact names/digests, and runner image. Do not run the bulk dispatcher as a canary.
7. **Deploy:** after build/validation gates and protected-environment approval, deploy the immutable Pages artifact. Verify the returned Pages URL and site health; roll back by redeploying the last known-good commit/artifact.

## Monitoring and weekly health checks

- Monitor failed/skipped gates, permission denials, environment approvals, artifact digests, cache misses, deployment URL/health, rollback invocation, repeated bot branches, and unexpected token/OIDC use.
- Weekly, run `python scripts/audit_github_actions.py --json` and `python scripts/workflow_doctor.py`; review action SHA provenance, deprecated action/runtime notices, permission drift, secret-reference drift, environment/ruleset drift, cache trust boundaries, artifact retention/digests, scheduled-run failures, and open automated repair PRs.
- Retain the workflow run URL, source commit, actor, inputs, job conclusions, artifact identifiers/digests, deployment decision, and rollback owner as the audit record.

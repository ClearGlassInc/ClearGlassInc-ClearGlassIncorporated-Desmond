# GitHub Actions remediation report

**Audit scope:** every YAML workflow in `.github/workflows/` at the audited commit.
**Method:** offline, read-only source inspection with `scripts/audit_github_actions.py`; no hosted workflow was dispatched.
**Execution gate:** repository environments, required reviewers, secret availability, action provenance, and rollback ownership cannot be proven from a checkout. A repository administrator must verify those controls before any deployment or mutating workflow is run.

## Outcome and repair order

1. **Fail closed on security gates.** Dependency review and secret scanning no longer suppress operational failures or critical dependency findings.
2. **Apply least privilege.** The military operations workflow no longer grants unused `id-token` and `security-events` write access to every job.
3. **Validate locally.** Run the auditor, its regression tests, YAML parsing, and `actionlint` when available.
4. **Approve remote rollout.** An administrator verifies protected environments, branch rules, Dependency Graph, Actions settings, secret names, and the rollback owner.
5. **Canary non-mutating workflows first.** Run CI/security checks at an immutable commit, record the run URLs and logs, then require human approval before Pages, releases, repository writes, or external deploy hooks.

## Classification criteria

- **valid and ready:** all source-verifiable controls pass; remote governance checks are still required before hosted execution.
- **valid but needs improvement:** valid source with a non-blocking hardening finding.
- **broken and requiring immediate patching:** invalid structure or a fail-closed source invariant is violated.
- **unsafe and requiring governance changes before execution:** mutation or deployment lacks a source-verifiable approval boundary.

Install and run `actionlint` at a reviewed, pinned version before remote execution. Do not replace the repository-aware auditor with a generic YAML parser: YAML 1.1 parsers can interpret the literal GitHub key `on` as a boolean.

### Remote preflight (administrator approval required)

1. Record commit SHA, actor, workflow/ref, inputs, environment, approval authority, and rollback owner.
2. Confirm Dependency Graph is enabled and required security checks are branch-protection gates.
3. Confirm `github-pages` and `production` are protected environments with required reviewers and branch restrictions.
4. Confirm every referenced secret name exists without reading or printing its value.
5. Verify GitHub Actions SHA provenance against the intended tagged releases.
6. Confirm the target branch and artifact identity are immutable and the last known-good commit/artifact is available.
7. Dispatch only a non-mutating canary first. Capture run URL, job conclusions, relevant log excerpts, and artifact IDs/digests.
8. Require a separate human approval before any deploy, release, issue creation, push, or external hook.

### Rollback

- **Workflow change:** revert the audit commit and rerun local validation; do not dispatch the reverted workflow until review completes.
- **GitHub Pages:** redeploy the last known-good Pages artifact/commit through the protected `github-pages` environment.
- **Release/tag:** never delete or rewrite an audited release tag automatically; stop and have the release owner issue a corrective release.
- **External deployment:** use the target platform's documented last-known-good artifact rollback only after the named operator approves it.

## Monitoring after deployment

Monitor job conclusion and latency, queue time, cancellation rate, environment approval decisions, artifact digest/retention, dependency and secret-scan findings, OIDC/token authorization failures, Pages health, and unexpected repository mutations. Alert on skipped required jobs, missing artifacts, permission escalation, action-ref drift, or deployments not tied to the approved commit.

## Weekly health checks

- Run the offline auditor and `actionlint`; diff the machine-readable inventory.
- Verify all action refs remain full 40-character SHAs and review upstream security advisories before updating pins.
- Review effective workflow/job permissions, checkout credential persistence, schedules, concurrency, caches, artifacts, and deployment environments.
- Confirm Dependency Graph, branch protection, required reviewers, secret rotation ownership, artifact retention, and rollback artifacts remain healthy.
- Sample completed runs for audit completeness: commit, actor, ref/inputs, approvals, run URL, logs, artifact IDs/digests, and rollback owner.
- Exercise a non-production rollback and document recovery time; do not infer production readiness from configuration alone.
